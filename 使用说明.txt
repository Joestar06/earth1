────────────────────────────────
关于动效层
────────────────────────────────
动效层不修改 earthory.css 与 earthory.js，包含：

· 页面进场遮罩与页面间切换淡入淡出
· 滚动进场：文字、卡片、图片按层次依次浮现
· 顶部滚动进度条；向下滚动隐藏、向上滚动回来的吸顶导航
· 首屏氛围层：呼吸光晕、缓慢漂移的网格、掠过的光带、悬浮微粒
· 影像取景框 HUD：四角框线、循环扫描线、背景视差
· 「个人世界模型」：中心球到五个维度的连线绘制、流动光点、同心环旋转
· 三段式原理条：数据在各环节之间流动
· 深色区块：点阵网格与呼吸辉光
· 卡片跟随鼠标的光斑、轻微 3D 倾斜、抬起投影
· 按钮磁吸跟随与高光扫过
· 时间轴随滚动逐段点亮

如需完全关闭动效，在 6 个 HTML 文件中各删掉两行：
  <link rel="stylesheet" href="earthory-motion.css">
  <script src="earthory-motion.js"></script>
（新增三页还需保留 earthory-pages.js，图标依赖它。）

系统开启「减弱动态效果」（Windows 与 macOS 的无障碍设置）时，
动效会自动降级为无动画的静态版本。

────────────────────────────────
调整动画快慢
────────────────────────────────
两个地方，改完刷新即可，不需要重新构建：

1) 元素之间的先后节奏
   earthory-motion.js 第 20 行：  var SPEED = 0.5;
   调小更快（0.3 几乎同时出现），调大更慢（1.0 是最初的节奏）。

2) 单个元素的动画时长
   earthory-motion.css 顶部：
     --eo-d:.58s;        普通淡入上移
     --eo-d-mask:.78s;   标题的遮罩擦除

滚动触发点在 earthory-motion.js 的 IntersectionObserver 里，
rootMargin 的第三个值（现为 90px）表示元素还差多少进入视口就开始播放，
调大 = 更早开始。

────────────────────────────────
导航为什么由脚本补齐
────────────────────────────────
index / hardware / app 三页的导航栏和页脚由已压缩的 earthory.js 渲染，
无法直接改源码。因此 earthory-motion.js 会在运行时：
  · 把「工作方式 / 隐私与安全」从首页锚点改指向 how.html / privacy.html
  · 补上「招聘」入口
  · 高亮当前所在页面
新增的三页则直接写在 HTML 里，两边最终一致。

────────────────────────────────
移动端导航（全站）
────────────────────────────────
问题：earthory.css 里有一句

    @media(max-width:900px){ .nav nav{display:none} }

把导航整个藏掉，却没有补任何替代入口。手机上除了 logo 和「下载」，
五个页面全都进不去，只能滚到页脚找链接。客户反馈的「目录消失了」
就是这个。顺带地，导航消失后 .nav nav 的 margin-left:auto 也没了，
「下载」按钮会贴到 logo 旁边而不是靠右。

做法：earthory-motion.js 的 8.8 节
    · 汉堡按钮在运行时插进 .nav（首页/硬件页/App 页的导航由
      earthory.js 渲染，改不了源码，只能这样补）
    · 面板挂在 body 上，不在 .site-shell 里——那个容器有
      overflow:hidden，放里面会被裁掉
    · 面板里的链接每次打开时从当前 DOM 现读，永远和顶部导航一致，
      React 重渲染也不会不同步
    · 关闭时机：点链接、Escape、拉宽到 900px 以上、翻页动效触发时
    · 打开时锁住背后滚动，关闭后焦点还给按钮

样式在 earthory-pages.css 末尾「移动端导航」那一段，
断点 900px 要和 earthory.css 里那句保持一致，改一个就要改另一个。

翻页动效那里有个坑：静态文件模式下的点击拦截在捕获阶段就调了
stopPropagation()，面板自己的关闭逻辑收不到事件，所以在那个
处理器里显式调了一次 mnavClose()。

还有一个坑：面板 z-index 90，.nav 只有 10，面板一开就把导航条整个
盖住了——汉堡按钮在底下既看不见也点不到，手机又没有 Esc 键。
所以面板头部必须自带一个关闭按钮（.eo-mnav-x），否则打开之后
只能靠点某条链接离开当前页。按钮在 mnavPanel() 里建。
注意 mnavFill() 往 .eo-mnav-brand 里写 innerHTML，不是往
.eo-mnav-top——写到 top 上会把关闭按钮一起冲掉。

────────────────────────────────
移动端观感（全站）
────────────────────────────────
原来的两个断点（900 / 560）只做了布局塌缩，多列变一列。
这一段补的是塌缩之后剩下的东西，全在 earthory-pages.css 末尾
「移动端观感」那一节，按 1~11 编号，每条都写了为什么。

真正会被用户察觉的四条：

  iOS 聚焦输入框会放大整页
      Safari 在聚焦 font-size 小于 16px 的输入框时缩放视口，而且
      失焦不缩回去。「加入我们」那张表原来 font:inherit 继承的是
      label 的 13px，每点一个字段页面就跳一次。现在手机上统一 16px。
      注意 .join-form input 的权重是 (0,2,0)，光写 input{} 压不住，
      必须点名；.join-result textarea 用了 font 简写，同理。

  页脚七条链接横向溢出
      footer div 是不换行的 flex，12px 字号下也要五百多像素，
      手机只有三百出头，结果 Earthory One 被从中间折断。
      改成两列网格。以后加链接不会再溢出。

  品类三句话被压成三条窄柱
      .principle-strip 是 flex 且没有 flex-wrap，约 40 个汉字挤在
      375px 里，原来降到 11px 也读不了。手机上改成竖排一句一行、
      15~16px，句间加一条淡分隔线。motion.css 那个逐句点亮的动画
      竖排后照常工作。首页（8.6 的 CATEGORY）和 how.html 都受益。

  触屏上的 :hover 残留
      手机没有指针，点完之后 hover 卡住不走——卡片浮起来不落下、
      图片一直放大着。统一收进 @media(hover:none)，换成 :active
      的按压反馈。以后新加 hover 效果记得一并加进那一段。

其余七条：文字自动放大（-webkit-text-size-adjust）、点击闪光换成
品牌色、刘海与 home indicator 的 env() 留白、中文标题的负字距归零
（负值是给拉丁文收紧用的，套在方块字上只会挤成一团）、点击目标
补到 42px 以上（岗位列表原来只有 36px，那一页有四十多条）、
首屏两个按钮竖排后等宽、板块间距整体收一档（76px → 64px）。

改断点的时候：900 和 560 这两个数散落在三张表里，
earthory.css 是压缩过的构建产物不要动，改就改 earthory-pages.css。

────────────────────────────────
部署（Vercel）
────────────────────────────────
配置在 vercel.json。三件事必须是现在这样，改了会出问题：

  buildCommand    一个 echo 空跑
  outputDirectory "."
  cleanUrls       false

为什么要显式关掉构建：
Vercel 看到 package.json 里有 build 脚本，就会当成前端框架项目去跑
构建，然后找 public/ 输出目录。但我们的 npm run build 是**就地改文件**
的生成器，不产出任何目录，于是报
    No Output Directory named "public" found
显式写死这三项，它就不猜了，直接把仓库根目录当成静态站发出去。

**cleanUrls 一定要保持 false。**
开了之后 /how.html 会被 301 到 /how，而所有 canonical、sitemap、
hreflang 里写的都是带 .html 的地址——那会变成全站 canonical 和实际
URL 对不上，比没有 canonical 更糟。

生成的文件都已提交进仓库，所以线上不需要构建。
**代价是：改了源文件必须先在本地跑 npm run build 再提交**，
否则线上是旧内容。提交前跑一次 npm run check 能挡住大部分疏漏。

.vercelignore 里排掉了 tools/、supabase/、package.json 和使用说明。
robots.txt 虽然 Disallow 了 tools 和 supabase，但那只是请爬虫别抓，
文件本身照样能被直接访问，不发上去更干净。

响应头：HTML 和配置文件不缓存（改了要立刻生效），assets 和 downloads
长缓存一年（换图会换文件名），JS/CSS 一小时（文件名没有内容哈希，
改了是同名覆盖，不能长缓存）。

上线后还要在 Vercel 后台配：
  · 绑定 earthory.com 和 www.earthory.com
  · 裸域 301 到 www（或反过来，选一个），不做的话 Google 会当成两个站
  · ALLOWED_ORIGINS 已经是 https://earthory.com,https://www.earthory.com，
    如果最终用的是别的域名（比如先用 vercel.app 试），
    要在 Supabase 那边把新域名加进去，否则两个表单都会被 403 挡掉

────────────────────────────────
双语站：英文在根，中文在 /zh/
────────────────────────────────
    /            英文（主语言，x-default）
    /zh/         中文
    右上角        EN / 中文 两格胶囊，当前那格填色

为什么英文占根目录而不是 /en/：
静态托管做不了服务端 301，根目录只能是一个真实页面。要让英文当
主语言，它就必须占住 /。在 / 放一个跳到 /en/ 的 meta refresh，
等于把全站最值钱的 URL 浪费在一个跳转页上。

一条命令重建整站：
    npm run build

它依次跑：抽取翻译 → 生成英文 JS → 生成英文定价配置 →
写入双语 SEO 元数据 → 预渲染两套 React 页。
改完任何源文件都跑一次，然后 npm run check 自检。

── 翻译是表驱动的，不是维护两份 ──
中文是源，英文由翻译表生成。三份表：

    tools/i18n/zh.json      JS 里的字符串（4 个文件，333 条）
    tools/i18n/html.json    静态页的文案（614 条）
    tools/i18n-pricing.js   定价配置（77 条，直接写在脚本里）

**改英文文案就改表，不要直接改 .en.js 或根目录的 HTML**——
下次 npm run build 会整个覆盖掉。改中文就改源文件。

为什么不手写两份：两份会立刻开始漂移，改了中文忘了改英文，
两个月后没人知道哪边是对的。

── 生成出来的文件（不要手改）──
    earthory.en.js            由 earthory.js 生成
    earthory-content.en.js
    earthory-motion.en.js
    earthory-pages.en.js
    pricing-config.json       由 pricing-config.zh.json 生成（英文是主，所以不带后缀）
    根目录的 9 个 .html        由 /zh/ 下同名文件生成
    robots.txt / sitemap.xml

原始的 earthory.js 一个字节都没动。压缩过的包没有源码，
做法是构建时按表重写里面的字符串字面量，改完做语法检查。

── 语言切换 ──
在 earthory-motion.js 的 8.10 节。两种语言是同名文件，
差别只有 /zh 前缀，所以「另一种语言的同一页」= 加上或去掉前缀。

两个坑，都踩过：

1. ZH_LABEL 那个「中文」在翻译表里映射成它自己。不这么写的话，
   生成 earthory-motion.en.js 时会被翻成 "Chinese"，
   英文页上的按钮就没法用了。i18n.js 的残留检查也认识这种
   恒等翻译，不会误报。

2. 语言链接必须排除出 SPA 路由改写。它的 href 是 "/"，
   会被 ROUTE 映射成 index.html，从 /zh/ 解析出来是
   /zh/index.html——点了等于原地不动。现在带 hreflang 的
   链接一律跳过改写。

── 资源路径必须是绝对的 ──
earthory.js 里的图片原本是 ./assets/… 相对路径，中文页搬进 /zh/
之后会解析成 /zh/assets/… 而 404。现在全站统一 /assets/…，
两套语言树用完全相同的相对内链就能各自正确。

代价：不能再双击 HTML 文件打开，必须起 http 服务（npm run serve）。
反正读 pricing-config.json 本来就需要。

── 加一种语言要改的地方 ──
    tools/seo.config.json  的 locales 加一项
    tools/i18n.js          FILES 加一组输出
    tools/i18n-html.js     PAGES 加一组
    翻译表里补该语言的一列（现在的表是「中文 → 英文」单向，
    多语言要改成「中文 → {en, ja, …}」）

────────────────────────────────
SEO：三个生成器
────────────────────────────────
    npm run seo         生成每页的 head + robots.txt + sitemap.xml
    npm run prerender   把 React 三页渲染成静态 HTML
    npm run seo:check   自检
    npm run build       前两个一起跑

── 1. tools/seo.js ──
唯一数据源是 tools/seo.config.json。改标题、描述、域名都改那个文件，
然后跑 npm run seo，它会重写九个 HTML 的 head：
title / description / canonical / hreflang / Open Graph /
Twitter Card / JSON-LD，再生成 robots.txt 和 sitemap.xml。

为什么要生成不手写：八个页面手工维护，改一次域名要改八处 canonical、
八处 og:url，还得记得同步 sitemap。漏一处就是一个指向错地址的
canonical——那比没有 canonical 更糟。

head 里由它管理的部分夹在 <!-- SEO:BEGIN --> 和 <!-- SEO:END --> 之间，
**别手改那一段**，下次跑会被整段覆盖。区段外的东西（charset、viewport、
favicon、样式表）它一概不碰。

JSON-LD 用 @graph 把 Organization / WebSite / WebPage / BreadcrumbList
串成一张图，彼此用 @id 互相引用，比各写一个 script 更容易让爬虫
理解它们是同一个实体的不同侧面。

**organization.sameAs 现在是空的**，因为我不知道你们真实的社交账号地址。
填假 URL 会让 Google 判定这个 Organization 不可信，宁可不写。
账号开通后把真实链接填进 config，跑一次 seo 就会写进所有页面。

── 2. tools/prerender.js ──
这个解决的是执行方案第九条点名的问题。

index.html / hardware.html / app.html 原本只有一个空的
<div id="root"></div> 加一个 290KB 的 JS 包，HTML 里没有标题、
没有正文、没有链接——SEO 上就是三个空页面。

Googlebot 现在会执行 JS，但 Bingbot、以及 ChatGPT / Perplexity / Claude
这些 AI 抓取器大多不会。而「让 AI 系统认识 Earthory」正是这轮 SEO 的
核心目标，不能赌爬虫跑不跑 JS。

做法：用 jsdom 在构建时把页面跑出来，结果写回 #root。浏览器打开时
React 照常接管重新渲染，视觉零变化；区别只是爬虫和用户第一眼就拿到
真实内容（LCP 顺带变好）。效果：

    index.html      1069 字节  →  29 KB，1491 字正文
    hardware.html   1067 字节  →  22 KB，1249 字正文

── 顺带修掉的两个会在上线时才炸的 bug ──
预渲染把它们暴露了出来：

1. earthory.js 渲染的 href 是 /hardware、/app 这类 SPA 路由地址，
   而这个站是一组静态文件，没有服务端路由。原来只在**点击时**
   映射到真实文件，对有 JS 的用户够用，但爬虫不点击——它读到
   href="/hardware" 就直接去抓，拿到 404，而真正的 hardware.html
   一条内链都收不到。现在在 fixLinks() 里把 href 本身改掉了。

2. STATIC 的判定原来只认 /index.html，而线上首页的路径是 /。
   判定为 false 时，那个负责翻页的点击拦截器在真实域名的首页上
   **根本不会注册**，点导航会直接跳到不存在的 /hardware。
   现在加上了根路径判定。

── 算价公式 ──
配置器的价格由 pricing-config.json 的 formula 段算出：

  ( 场景基础费
    + 储存费（阶梯费率，越大越便宜）× 保存周期系数
    + AI 记忆保存费
    + 超出的设备数 × 单价
    + 超出的用户数 × 单价 ) × AI 处理量倍率

这套系数是照着五档标价套餐拟合的，最大偏差 0.9%：

  Personal    公式 12.80  标价 12.90
  Family      公式 30.17  标价 29.90
  Business    公式 98.57  标价 99.00
  Industrial  公式 299.74 标价 299.00

**改 formula 里任何系数之后，一定要复核这五档还对不对得上**，
否则会出现「照着套餐配一遍，配置器报价却差很多」的尴尬。
复核脚本在 scratchpad/fit.py，跑一下就知道。

任何一个维度选了 Custom / Enterprise（配置里值为 null），
整块就切换成「按需报价」，不出数字——瞎报一个价比不报更糟。

── 和原始需求不一致的两处 ──
1. 需求里那个例子「Business 5TB / 180天 / 5年 / 12设备 / 10用户 = S$189」
   和需求自己给的套餐价对不上。按 2TB=99、10TB=299 做线性插值，
   5TB 上限约 174，有阶梯折扣只会更低。公式算出来是 146.37。
   现在按 146 走。要改成 189 的话，2TB→10TB 那档费率得大幅上调，
   Industrial 就会从 299 涨到 430 左右。这是个定价决策，不是代码问题。

2. 设备数和用户数用的是数字输入框，不是需求里列的下拉选项。
   因为需求自己的例子是「12 台设备」，而给的下拉是 1/2/5/10/20/50/100，
   根本选不出 12。数字框两边都能满足。

销售对接窗口
────────────────────────────────
定价页上**所有** CTA 都打开这个窗口，不跳任何别的页面。

想买东西的人被丢进招聘表单，第一个问题还是「你想以什么身份加入」。
现在是独立窗口 + 独立接口 + 独立数据表，和招聘完全不共用。

  前端      earthory-pages.js 第 5 节里的 salesModal / openSales / submitSales
  样式      earthory-pages.css 末尾「销售对接窗口」
  接口      supabase/functions/sales/index.ts   POST /sales
  表        supabase/migrations/20260907000000_sales_enquiries.sql

窗口只问四件事：**名字、邮箱、联系方式、用途**。
一开始我摆了公司、职位、地区、什么时候要用上，八个字段一屏，
那是在赶人走——配置快照那一块已经把「客户要什么」说清楚了。

窗口会把用户**刚才配的东西一起带过去**——哪一档、多少存储、留多久、
几台设备几个用户、月付还是年付、页面上显示的预估价。销售拿到线索时
这些都在，不用回头再问一遍。从套餐卡打开就带那张卡的配置，
从配置器打开就带配置器当前的值。

同意勾选不能删，那是 PDPA 的举证依据。蜜罐字段用户看不见。

要加回某个字段（比如公司名）：表加一列、Edge Function 加一行 clean()、
窗口的 innerHTML 里加一个 input，三处，别漏。

数据库里存的是**快照不是外键**：以后改价格改套餐，历史线索仍然能还原
客户当时看到的是什么。est_price 是页面上的预估价，不是最终报价。

安全模型和 /join 完全一致：前端不持有任何密钥，表 RLS 拒绝一切，
只有 Edge Function 用 service_role 写得进去。蜜罐、IP 哈希限流、
CORS 白名单一样不少。数值字段（存储/设备/用户）在服务端重新解析并
夹在范围内——那几个在页面上是用户能改的输入框，传上来的数不能信。

限流用的是 SALES_MAX_PER_HOUR（默认 8），比招聘的 5 放宽，
因为一个公司里几个人分别来问价是正常的。

后台看线索：Table Editor → sales_enquiries。
status 是一条完整的销售流水线：
new / contacted / qualified / quoted / won / lost / spam，
另有 owner 字段给销售填跟进人。

**部署提醒**：新表和新函数都还没上线，需要跑
    npx supabase db push
    npx supabase functions deploy sales --no-verify-jwt
    npx supabase secrets set SALES_MAX_PER_HOUR="8"

兜底里都出现了，但 earthory.com 目前没有 MX 记录，这个邮箱收不到信。

APK 放在哪
────────────────────────────────
    earthory-static-website/downloads/Earthory-v0.3.5.apk

文件名按版本号命名，不用 latest 这种固定名。好处是换版本时 URL 也变了，
不会被 CDN 或浏览器缓存住旧包；用户下载后在手机里也能看出装的是哪一版。

换版本的步骤（download.html 里一共要改 6 处）：
    1. 新 APK 放进 downloads/，命名成 Earthory-v版本号.apk，删掉旧的
    2. 下载按钮的 href="downloads/Earthory-v新版本.apk"
    3. 同一个按钮的 download="Earthory-v新版本.apk"
       （download 属性是给忽略服务器文件名的浏览器兜底用的）
    4. 首屏 .dl-meta 里的版本号 / 体积 / 更新日期 / 最低系统版本
    5. 安装说明卡片里的 SHA-256
    6. 右侧 App 卡片上的「安卓体验版 v新版本」

Windows 上算 SHA-256：
    certutil -hashfile downloads\Earthory-v0.3.5.apk SHA256

上线时 downloads 文件夹要一起传到服务器。
用 Nginx 的话，确认 .apk 的 MIME 类型是
application/vnd.android.package-archive，否则有的浏览器会当文本打开。

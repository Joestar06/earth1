────────────────────────────────
关于动效层
────────────────────────────────
动效层不修改 earthory.css 与 earthory.js，包含：

· 页面进场遮罩与页面间切换淡入淡出
· 滚动进场：文字、卡片、图片按层次依次浮现
· 顶部滚动进度条；向下滚动隐藏、向上滚动回来的吸顶导航
· 首屏氛围层：呼吸光晕、缓慢漂移的网格、掠过的光带、悬浮微粒
· 影像取景框 HUD：四角框线、循环扫描线、背景视差
· 「个人世界模型」：中心球到五个维度的连线绘制、流动光点、同心环旋转
· 三段式原理条：数据在各环节之间流动
· 深色区块：点阵网格与呼吸辉光
· 卡片跟随鼠标的光斑、轻微 3D 倾斜、抬起投影
· 按钮磁吸跟随与高光扫过
· 时间轴随滚动逐段点亮

如需完全关闭动效，在 6 个 HTML 文件中各删掉两行：
  <link rel="stylesheet" href="earthory-motion.css">
  <script src="earthory-motion.js"></script>
（新增三页还需保留 earthory-pages.js，图标依赖它。）

系统开启「减弱动态效果」（Windows 与 macOS 的无障碍设置）时，
动效会自动降级为无动画的静态版本。

────────────────────────────────
调整动画快慢
────────────────────────────────
两个地方，改完刷新即可，不需要重新构建：

1) 元素之间的先后节奏
   earthory-motion.js 第 20 行：  var SPEED = 0.5;
   调小更快（0.3 几乎同时出现），调大更慢（1.0 是最初的节奏）。

2) 单个元素的动画时长
   earthory-motion.css 顶部：
     --eo-d:.58s;        普通淡入上移
     --eo-d-mask:.78s;   标题的遮罩擦除

滚动触发点在 earthory-motion.js 的 IntersectionObserver 里，
rootMargin 的第三个值（现为 90px）表示元素还差多少进入视口就开始播放，
调大 = 更早开始。

改内容

    每条通道的能力词条是 .chipset / .chips——这些列表很长，
    写成项目符号会变成读不完的清单，所以用 chip 排。
    .chips.solid 是实心样式，用来区分「合作方式」这类收尾组。

各通道底部的按钮
    href="#contact" + data-relation="…"，跳到表单时会自动把
    「关系类型」选好，省得对方滚到底再找一遍。
    data-relation 的值必须和表单里 radio 的 value 完全一致。

★ 表单后端在 supabase/ 目录下
    一张 Postgres 表 + 一个 Edge Function 当 API。
    完整部署步骤见 supabase/README.md，这里只说要点。

    没有让前端直连数据库。Supabase 常见做法是前端带 anon key 直接写
    PostgREST，但那样安全性全押在 RLS 策略写得对不对上，而这张表里
    是真实姓名和邮箱，写错一次就是泄露。现在是：
      · 表开 RLS 且不建任何 policy —— 前端角色一行都读不到写不了
      · 只有 service_role 写得进去，密钥只在 Edge Function 的环境变量里
      · 浏览器里一个密钥都没有
    看数据走 Supabase 后台 Table Editor。

    部署完，把函数地址填进 earthory-pages.js 顶部的 JOIN_API：
        var JOIN_API = 'https://<项目 ref>.supabase.co/functions/v1/join';
    留空也不会坏 —— 页面会退回「把内容整理好让对方自己复制发邮件」，
    所以后端没上线之前表单照样能用。

    防垃圾提交三层，都在服务端：蜜罐字段（命中返回 200 骗过机器人）、
    同 IP 每小时限流、relation 白名单 + 字段长度上限 + 数据库 CHECK。

    PDPA：提交必须勾选同意，consent 存进库里备查；IP 只存 SHA-256
    不存明文。还欠两件事 —— 保留期限没有自动清理，以及删除请求的
    处理流程，见 supabase/README.md 末尾。

────────────────────────────────
APK 放在哪
────────────────────────────────
    earthory-static-website/downloads/Earthory-v0.3.5.apk

文件名按版本号命名，不用 latest 这种固定名。好处是换版本时 URL 也变了，
不会被 CDN 或浏览器缓存住旧包；用户下载后在手机里也能看出装的是哪一版。

换版本的步骤（download.html 里一共要改 6 处）：
    1. 新 APK 放进 downloads/，命名成 Earthory-v版本号.apk，删掉旧的
    2. 下载按钮的 href="downloads/Earthory-v新版本.apk"
    3. 同一个按钮的 download="Earthory-v新版本.apk"
       （download 属性是给忽略服务器文件名的浏览器兜底用的）
    4. 首屏 .dl-meta 里的版本号 / 体积 / 更新日期 / 最低系统版本
    5. 安装说明卡片里的 SHA-256
    6. 右侧 App 卡片上的「安卓体验版 v新版本」

Windows 上算 SHA-256：
    certutil -hashfile downloads\Earthory-v0.3.5.apk SHA256

上线时 downloads 文件夹要一起传到服务器。
用 Nginx 的话，确认 .apk 的 MIME 类型是
application/vnd.android.package-archive，否则有的浏览器会当文本打开。
